# Structure with XML Tags (cấu trúc hóa bằng thẻ XML)

Khi bạn xây dựng các prompt có chứa nhiều content (nội dung), đôi lúc Claude sẽ gặp khó khăn trong việc hiểu những đoạn text (văn bản) nào thuộc về nhau, hay các section (phần) khác nhau đại diện cho điều gì. XML tags (thẻ XML) cung cấp một cách đơn giản để thêm structure (cấu trúc) và sự rõ ràng cho prompt của bạn, đặc biệt khi bạn đang interpolate (chèn vào) một lượng lớn data (dữ liệu).

## Vì sao Structure quan trọng

Hãy tưởng tượng một prompt mà bạn cần phân tích 20 trang sales record (bản ghi bán hàng). Nếu không có ranh giới rõ ràng, Claude có thể gặp khó khăn trong việc phân biệt đâu là instruction (chỉ dẫn) của bạn, đâu là data thực sự cần phân tích.

Ví dụ trên cho thấy ranh giới không rõ ràng có thể khiến Claude khó parse (phân tích, diễn giải) đúng ý định của bạn. Bằng cách bọc các sales record trong XML tags như `<sales_records>` và `</sales_records>`, bạn tạo ra các delimiter (dấu phân cách) rõ ràng, giúp Claude hiểu được structure của prompt.

## Ví dụ thực tế: Code và Documentation (tài liệu)

Đây là một ví dụ rõ ràng hơn về lý do XML tags quan trọng. Nếu bạn yêu cầu Claude debug (gỡ lỗi) code bằng cách dùng documentation được cung cấp, việc trộn lẫn mọi thứ với nhau sẽ tạo ra sự nhầm lẫn:

Phiên bản "Not Great" (chưa tốt) khiến gần như không thể phân biệt được đâu là code, đâu là documentation. Phiên bản "Better" (tốt hơn) dùng tag `<my_code>` và `<docs>` để tạo ra ranh giới rõ ràng.

## Custom Tag Names (đặt tên tag tùy chỉnh)

Bạn không cần phải dùng các official XML tag (thẻ XML chính thức). Hãy tạo ra những cái tên mô tả (descriptive) phù hợp với nội dung của bạn:

* `<sales_records>` tốt hơn là `<data>`
* `<athlete_information>` xác định rõ ràng thông tin vận động viên
* `<my_code>` và `<docs>` tách biệt các loại content khác nhau

Tag name (tên thẻ) càng cụ thể và mô tả rõ ràng, Claude càng dễ hiểu mục đích của từng section.

## Khi nào nên dùng XML Tags

XML tags hữu ích nhất khi:

* Đưa vào một lượng lớn context (ngữ cảnh) hoặc data
* Trộn lẫn nhiều loại content khác nhau (code, documentation, data)
* Bạn muốn thật rõ ràng về ranh giới của content
* Làm việc với các prompt phức tạp có interpolate nhiều variable (biến số)

Ngay cả với content ngắn, XML tags vẫn có thể đóng vai trò delimiter giúp structure của prompt trở nên rõ ràng hơn đối với Claude.

## Ứng dụng thực tế

Trong thực tế, bạn có thể cấu trúc một prompt như sau:

```
<athlete_information>
- Height: 6'2"
- Weight: 180 lbs
- Goal: Build muscle
- Dietary restrictions: Vegetarian
</athlete_information>

Generate a meal plan based on the athlete information above.
```

Cách này làm rõ ràng tuyệt đối rằng height (chiều cao), weight (cân nặng), goal (mục tiêu), và restriction (hạn chế) đều là các athlete data (dữ liệu vận động viên) liên quan với nhau, cần được xem xét cùng nhau khi generate (sinh ra) meal plan (thực đơn).

Dù bạn có thể không thấy cải thiện rõ rệt với các prompt đơn giản, XML tags sẽ ngày càng trở nên có giá trị khi prompt của bạn phức tạp hơn và chứa lượng content đa dạng lớn hơn.
