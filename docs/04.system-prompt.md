Dưới đây là bản tóm tắt về **System Prompts**:

## Tại sao System Prompts quan trọng

Ví dụ: xây dựng chatbot làm math tutor. Khi student hỏi "How do I solve 5x + 2 = 3 for x?", bạn muốn Claude hành xử như một tutor thật sự, chứ không phải chỉ nhả ra đáp án.

Một tutor tốt nên:
- Đưa ra hint trước, chưa vội đưa solution hoàn chỉnh
- Kiên nhẫn dẫn dắt student qua từng bước
- Đưa ví dụ tương tự để minh họa

Không nên:
- Trả lời trực tiếp ngay lập tức
- Bảo student "cứ dùng calculator đi"

## Cơ chế hoạt động

System prompt là một plain string, truyền vào `create()` function. Bản chất:
- Định hướng cách Claude respond
- Claude sẽ cố gắng phản hồi đúng như role đã set
- Giúp Claude bám sát task, tránh lan man

**Cấu trúc cơ bản:**
```python
system_prompt = """
You are a patient math tutor.
Do not directly answer a student's questions.
Guide them to a solution step by step.
"""

client.messages.create(
    model=model,
    messages=messages,
    max_tokens=1000,
    system=system_prompt
)
```

## Sự khác biệt rõ rệt

- **Không có system prompt:** Claude đưa full step-by-step solution ngay lập tức.
- **Có system prompt (math tutor):** Claude chuyển sang hỏi dẫn dắt kiểu "bước đầu tiên để isolate x nên làm gì?", thay vì đưa đáp án.

## Xây dựng chat function linh hoạt

```python
def chat(messages, system=None):
    params = {
        "model": model,
        "max_tokens": 1000,
        "messages": messages,
    }
    
    if system:
        params["system"] = system
    
    message = client.messages.create(**params)
    return message.content[0].text
```

**Lưu ý kỹ thuật quan trọng:** API của Anthropic **không chấp nhận `system=None`** — đây là lý do phải dùng conditional check (`if system:`) để chỉ đưa `system` param vào dict khi nó thực sự được cung cấp, tránh lỗi khi gọi API.

**Cách gọi:**
```python
# Không có system prompt
answer = chat(messages)

# Có system prompt
system = """..."""
answer = chat(messages, system=system)
```

---

**Góc nhìn Backend (liên hệ với thứ anh hay làm):** Pattern tách `system` prompt ra khỏi `messages` list ở đây tương tự việc anh tách config/middleware layer ra khỏi business logic trong Laravel hay NestJS — `system` đóng vai trò như một "global constraint layer" áp lên toàn bộ conversation, còn `messages` là data thuần túy của luồng xử lý. Về mặt kiến trúc, nên treat system prompt như một **artifact cần version control** riêng (không hardcode rải rác trong code) vì nó ảnh hưởng trực tiếp đến hành vi và chất lượng output của cả hệ thống.
