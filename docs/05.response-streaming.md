# Streaming (truyền phát) Response

Khi xây dựng chat application (ứng dụng trò chuyện) với Claude, có một thách thức lớn về user experience (trải nghiệm người dùng): response (phản hồi) có thể mất từ 10-30 giây để generate (sinh ra), khiến user (người dùng) phải ngồi nhìn loading spinner (biểu tượng xoay chờ). Giải pháp là response streaming (truyền phát phản hồi theo luồng), cho phép user thấy text (văn bản) xuất hiện dần từng chunk (đoạn nhỏ) khi Claude generate, tạo cảm giác responsive (phản hồi nhanh nhạy) hơn nhiều.

## Vấn đề với Standard Response (phản hồi tiêu chuẩn)

Trong một chat setup (thiết lập trò chuyện) thông thường, server của bạn gửi user message (tin nhắn người dùng) đến Claude và chờ đến khi có complete response (phản hồi hoàn chỉnh) mới gửi gì đó về lại client (ứng dụng khách). Điều này tạo ra một khoảng delay (độ trễ) khó chịu, khi user không nhận được bất kỳ feedback (phản hồi) nào cho biết có việc gì đang diễn ra.

## Streaming hoạt động như thế nào

Khi bật streaming, Claude ngay lập tức gửi lại một response ban đầu báo hiệu đã nhận được request (yêu cầu) và đang bắt đầu generate text. Sau đó bạn sẽ nhận được một chuỗi events (sự kiện), mỗi event chứa một phần nhỏ của toàn bộ response.

Server của bạn có thể forward (chuyển tiếp) các text chunk này đến client application ngay khi chúng đến, cho phép user thấy response được build (xây dựng) dần từng từ một. Tất cả các event này đều thuộc về một request duy nhất gửi đến Claude.

## Hiểu về Stream Event (sự kiện luồng)

Khi bật streaming, Claude gửi lại nhiều loại event khác nhau:

* **MessageStart** – Một message (tin nhắn) mới đang được gửi đi
* **ContentBlockStart** – Bắt đầu một block (khối) nội dung mới, chứa text, tool use (sử dụng công cụ) hoặc content (nội dung) khác
* **ContentBlockDelta** – Các chunk chứa text thực sự được generate
* **ContentBlockStop** – content block hiện tại đã hoàn tất
* **MessageDelta** – message hiện tại đã hoàn chỉnh
* **MessageStop** – Kết thúc thông tin về message hiện tại

Event **ContentBlockDelta** chứa text thực sự được generate mà bạn sẽ muốn hiển thị cho user.

## Cách triển khai Streaming cơ bản

Để bật streaming, thêm `stream=True` vào lệnh gọi `messages.create`:

```python
messages = []
add_user_message(messages, "Write a 1 sentence description of a fake database")

stream = client.messages.create(
    model=model,
    max_tokens=1000,
    messages=messages,
    stream=True
)

for event in stream:
    print(event)
```

## Simplified Text Streaming (truyền phát văn bản đơn giản hóa)

Thay vì tự parse (phân tích) từng event một cách thủ công, bạn có thể dùng simplified streaming interface (giao diện truyền phát đơn giản hóa) của SDK để trích xuất riêng phần text content:

```python
with client.messages.stream(
    model=model,
    max_tokens=1000,
    messages=messages
) as stream:
    for text in stream.text_stream:
        print(text, end="")
```

Cách tiếp cận này tự động filter (lọc bỏ) mọi thứ ngoại trừ text content thực sự — đây thường là phần bạn cần để hiển thị response cho user.

## Lấy Complete Message (tin nhắn hoàn chỉnh)

Trong khi streaming từng chunk riêng lẻ mang lại trải nghiệm tốt cho user, bạn thường vẫn cần complete message để lưu trữ (storage) hoặc xử lý tiếp (further processing). Sau khi streaming hoàn tất, bạn có thể lấy được final message (tin nhắn cuối cùng) đã được lắp ráp đầy đủ:

```python
with client.messages.stream(
    model=model,
    max_tokens=1000,
    messages=messages
) as stream:
    for text in stream.text_stream:
        # Gửi từng chunk đến client của bạn
        pass
    
    # Lấy complete message để lưu vào database
    final_message = stream.get_final_message()
```

Cách này cho bạn cả hai lợi ích cùng lúc: real-time streaming (truyền phát theo thời gian thực) cho user, và một complete message object (đối tượng tin nhắn hoàn chỉnh) cho application logic (logic ứng dụng) của bạn.
