Dưới đây là bản tóm tắt về khái niệm **stateless conversation** trong Anthropic API:

## Vấn đề cốt lõi

Claude API là **stateless** — không tự lưu trữ conversation history. Mỗi request hoàn toàn độc lập, Claude không có memory về các exchange trước đó.

**Ví dụ minh họa:** Hỏi "What is quantum computing?" → nhận response tốt. Follow-up bằng "Write another sentence" → Claude sẽ không hiểu ngữ cảnh, có thể viết về chủ đề ngẫu nhiên vì không nhớ đoạn hội thoại trước.

## Cách maintain context

Muốn có multi-turn conversation, phải tự quản lý state ở phía code (client-side), cụ thể:

1. Tự maintain một list chứa toàn bộ messages
2. Gửi **toàn bộ** message history trong mỗi request, không chỉ message mới nhất

**Flow chuẩn:**
1. Gửi user message đầu tiên
2. Lấy response của Claude → append vào messages list dưới dạng `assistant` message
3. Thêm câu hỏi follow-up như một `user` message mới
4. Gửi lại **toàn bộ** conversation history (không phải chỉ câu follow-up)

## Helper functions

```python
def add_user_message(messages, text):
    user_message = {"role": "user", "content": text}
    messages.append(user_message)

def add_assistant_message(messages, text):
    assistant_message = {"role": "assistant", "content": text}
    messages.append(assistant_message)

def chat(messages):
    message = client.messages.create(
        model=model,
        max_tokens=1000,
        messages=messages,
    )
    return message.content[0].text
```

## Ví dụ áp dụng

```python
messages = []

add_user_message(messages, "Define quantum computing in one sentence")
answer = chat(messages)
add_assistant_message(messages, answer)

add_user_message(messages, "Write another sentence")
final_answer = chat(messages)
```

Nhờ append đầy đủ history vào `messages` list trước khi gọi `chat()` lần 2, Claude mới hiểu "Write another sentence" đang ám chỉ mở rộng thêm về định nghĩa quantum computing ở lượt trước.

**Góc nhìn kỹ thuật (vì anh làm Backend/Laravel-NestJS):** Pattern này về bản chất giống hệt việc anh tự implement session/context management ở tầng application thay vì để server tự handle — điểm cần lưu ý khi scale là **token cost tăng tuyến tính theo độ dài hội thoại** vì mỗi request phải gửi lại toàn bộ history, nên với các đoạn chat dài cần có chiến lược truncate/summarize history để tránh vượt context window và tối ưu chi phí.
